# PAR'BAR — чек-листы смены

Утро, смена и закрытие в одном приложении. Все, кто открыл ссылку, видят отметки друг друга в реальном времени.

Файлы: `par-bar.html`, `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png`, `icon-180.png`.

---

## 1. Выложить на GitHub Pages

1. Создай публичный репозиторий, например `shift`.
2. Загрузи туда все файлы (Add file → Upload files).
3. Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`. Save.
4. Через 1–2 минуты появится адрес вида `https://ТВОЙ-НИК.github.io/shift/`.

На этом этапе приложение уже работает, но галочки живут только на одном телефоне. Дальше — общая база.

---

## 2. Подключить Firebase (общие галочки)

1. Зайди на `console.firebase.google.com`, создай проект. Google Analytics можно отключить.
2. Слева: **Build → Realtime Database → Create Database**. Регион — любой ближний (europe-west1). Запустить в **test mode**.
3. Слева вверху: **Project settings → Your apps → Web (`</>`)**. Зарегистрируй приложение, скопируй объект `firebaseConfig`.
4. Открой `par-bar.html`, найди блок `const FIREBASE = {` вверху скрипта и вставь значения:

```js
const FIREBASE = {
  apiKey: "AIza...",
  authDomain: "твой-проект.firebaseapp.com",
  databaseURL: "https://твой-проект-default-rtdb.europe-west1.firebasedatabase.app",
  projectId: "твой-проект"
};
```

`databaseURL` обязателен — без него приложение остаётся в локальном режиме.

5. Правила базы (вкладка **Rules**). Test mode отключается через 30 дней, поэтому замени на такие:

```json
{
  "rules": {
    "checklists": { ".read": true, ".write": true },
    "staff":      { ".read": true, ".write": true },
    "adj":        { ".read": true, ".write": true }
  }
}
```

Это открытый доступ по ссылке: кто знает адрес — тот пишет. Для внутреннего чек-листа бара нормально, но не храни там ничего личного. Если позже понадобится ограничить — включи Firebase Authentication и поменяй `true` на `"auth != null"`.

6. Залей обновлённый `par-bar.html` обратно в репозиторий.

---

## 3. Поставить на телефон

**Android (Chrome):** открыть ссылку → меню (⋮) → «Установить приложение» / «Добавить на главный экран».

**iPhone (только Safari, не Chrome):** открыть ссылку → кнопка «Поделиться» → «На экран "Домой"».

Иконка появится на рабочем столе, приложение откроется без адресной строки.

---

## 4. Как этим пользоваться

Три раздела вверху: **Открытие**, **Смена**, **Закрытие**. У каждого свои зоны и свой прогресс.

- При первом запуске каждый вводит имя — оно подписывается рядом с отметкой.
- Вкладки под переключателем — зоны. Заливка на вкладке показывает прогресс зоны.
- Нажатие на строку ставит и снимает галочку. Рядом видно, кто и во сколько отметил.
- Числовые поля (пауэрбанки, размен, суммы пересчётов, выручка) сохраняются, когда убираешь палец с поля.
- Вкладка **Все зоны** — экран для управляющего: прогресс каждой зоны и что осталось. Обновляется сам.
- **Сбросить** снимает отметки только текущего раздела за сегодня. Нужна редко: новая смена начинается сама.
- День смены переключается в 6 утра — ночные часы относятся к прошедшей смене. Меняется в `SHIFT_START_HOUR`.

## 5. Штрафы и надбавки

Раздел **Смена → Персонал**.

- Человек появляется в списке автоматически, как только введёт своё имя в приложении.
- Обычный сотрудник видит там только свою карточку и свои начисления.
- Управляющий нажимает «Войти как управляющий», вводит код из `MANAGER_PIN` в `par-bar.html` (по умолчанию `2580` — поменяй) и после этого видит всю смену, может открыть любого, ввести сумму с причиной и нажать «Штраф» или «Надбавку». Свои записи он же может удалить.
- У сотрудника итог за смену показывается плашкой под прогрессом, рядом со своей зоной. Нажатие открывает расшифровку: суммы, причины, кто и во сколько поставил.
- Начисления привязаны к дате смены и не сбрасываются кнопкой «Сбросить» — она трогает только галочки.

### История

Вкладка **Смена → История** — последние 30 дней.

- Управляющий видит сверху итог по каждому сотруднику за период, ниже все записи по датам: сумма, за что, кто поставил и во сколько. Любую запись можно удалить.
- Сотрудник видит только свои записи, без кнопок удаления.
- Данные подгружаются один раз при открытии вкладки; кнопка «Обновить» внизу перечитывает их заново.
- Глубину истории меняет `HISTORY_DAYS` в `par-bar.html`.

Человек опознаётся по имени, которое он ввёл при первом запуске. Если кто-то напишет себя по-разному («Руслан» и «Руслан В»), в истории это будут два разных человека — проследи, чтобы все вводили имя одинаково.

Честно про защиту: код управляющего лежит в открытом виде в `par-bar.html`, и правила базы выше разрешают запись всем. Любой, кто откроет исходник страницы, сможет ставить штрафы. Для внутреннего инструмента на доверии это терпимо, но если штрафы влияют на зарплату — нужен Firebase Authentication и правила вида `".write": "auth.uid === '<id управляющего>'"`. Скажи, если дойдёт до этого, настроим.

Отдельно: денежные штрафы работникам Трудовым кодексом не предусмотрены, удержания из зарплаты ограничены ст. 137 ТК РФ. Приложение просто фиксирует то, что решило заведение.

## 6. Свои задачи

В `par-bar.html` найди массив `LISTS`. Формат пунктов:

```js
"Обычная галочка",
{ h: "Заголовок раздела" },
{ n: "Памятка без галочки" },
{ t: "Сумма размена",   type: "num",    unit: "₽" },
{ t: "Что в стопе",     type: "text",   ph: "Подсказка в пустом поле" },
{ t: "Готово к 12:00",  type: "choice", options: ["Да", "Нет"] },
```

Зоны официантов берутся из функций `waiterZone()` (открытие) и `waiterZoneClose()` (закрытие) — правишь один раз, меняется во всех трёх.

Важно: отметки хранятся по порядковому номеру пункта в массиве. Если вставить пункт **в середину** списка посреди смены, отметки ниже сместятся. Добавляй в конец, а перестановки делай до открытия.
